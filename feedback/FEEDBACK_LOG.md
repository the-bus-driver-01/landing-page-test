## Feedback Entry Template

When adding new feedback, use this structure and add it to the appropriate section:

```markdown
### Feedback #[ID]

**Date**: [Date]
**Reviewer**: [Name]
**Category**: [Code Quality / Testing / Accessibility / Performance / UX/Design / Documentation / Security]
**Severity**: [Critical / Important / Nice-to-have]
**Status**: [Pending / In Progress / Resolved / Archived]

**Summary**:
[2-3 sentence overview of the feedback]

**Details**:
- Point 1
- Point 2
- Point 3

**Suggested Action**:
[Clear action to address this feedback]

**Owner**: [Who's responsible for addressing this]
**Target Date**: [When this should be addressed]

**Resolution** (if status is Resolved or Archived):
[How it was resolved or why it was archived]

**Notes**:
[Any additional context or discussion]
```

## How to Use This Log

### For Reviewers
1. Submit feedback using the template in `FEEDBACK_SUBMISSION_TEMPLATE.md`
2. Copy your feedback into this log
3. Assign a unique ID (Feedback #[sequential number])
4. Set initial status as "Pending" or "In Progress"

### For Project Leads
1. Review new feedback weekly
2. Prioritize critical issues
3. Assign owners and target dates
4. Track progress toward resolution
5. Update statistics regularly

### For the Team
1. Check the log regularly for updates
2. Address assigned feedback
3. Update status as you work
4. Discuss in retrospectives
